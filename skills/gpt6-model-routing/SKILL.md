# GPT-6 模型路由

根据任务的清晰度、重复程度、判断难度、工具数量、失败代价和交付价值选模型。模型名与推理档位是独立维度；技能不能改变当前对话的模型或档位，也不能把自然语言角色当成模型切换。

## 三档选择

- **GPT-6 Luna**（`gpt-6-luna`）：清晰、重复、高频、成本敏感任务，例如批量整理、机械修改、格式转换和边界稳定的局部操作。
- **GPT-6.1 Sol**（`gpt-6.1-sol`）：日常主力，适合常规编码、研究、调试、需要判断力的 Agent 工作流和多步骤实现。
- **GPT-6 Astra**（`gpt-6-astra`）：最高难度、跨工具、多步骤、高技艺或高价值任务，例如根因不明的复杂排查、架构决策、关键发布验收和高风险取舍。

默认不要因为任务重要就自动升级到 Astra；先判断不确定性、依赖数量和错误代价。图片中的标准输入/输出价格仅作参考（每百万 token）：Luna $0.10 / $0.50，Sol $2 / $10，Astra $10 / $50。价格、上下文和可用路由以宿主实时目录或官方定价为准，不据此承诺固定节省比例。

## 推理档位

- `low`：单步、局部、容易核验。
- `medium`：日常多步骤工作，默认起点。
- `high`：复杂实现、较多依赖、多个方案比较或严谨调试。
- `xhigh` / `max`：仅在确实高不确定、高价值且验收困难时使用，避免作为日常起始档位。
- `ultra`：仅当宿主和所选模型支持，且前述档位仍不足时使用。

以宿主实时模型定义为准；若模型或档位不可用，报告差异，不冒充执行成功。

## 实际工作分工

需要实际改动时，先明确目标、范围、依赖、推荐模型/档位和验收标准。默认使用一个足够的执行者；仅在子任务真正独立、文件归属不冲突且并行有收益时并行。

执行者负责实现、自测和必要修复，不自行改模型、升档、递归委派或作最终验收。主代理独立检查实际 diff、产物和验证证据；失败时给出带证据的定向返工任务，修复后再次验收。

支持模型覆盖的委派工具应显式传入 `model`、`reasoning_effort`；跨模型委派使用 `fork_turns: "none"`。委派消息应包含目的、范围、验收项、工作目录、相关文件和交付格式。

不要未经用户要求设置硬 token 或金额预算。委派增加规划、交接、报告和验收上下文，小任务可能不值得拆分。
