# GPT-6 模型路由

根据任务的清晰度、重复程度、判断难度、工具数量、失败代价和交付价值选模型。模型名与推理档位是独立维度；技能不能改变当前对话的模型或档位，也不能把自然语言角色当成模型切换。

## 三档选择

- **GPT-6 Luna**（`gpt-6-luna`）：清晰、重复、高频、成本敏感任务，例如批量整理、机械修改、格式转换和边界稳定的局部操作。
- **GPT-6.1 Sol**（`gpt-6.1-sol`）：日常主力，适合常规编码、研究、调试、需要判断力的 Agent 工作流和多步骤实现。
- **GPT-6 Astra**（`gpt-6-astra`）：最高难度、跨工具、多步骤、高技艺或高价值任务，例如根因不明的复杂排查、架构决策、关键发布验收和高风险取舍。

默认不要因为任务重要就自动升级到 Astra；先判断不确定性、依赖数量和错误代价。图片中的标准输入/输出价格仅作参考（每百万 token）：Luna $0.10 / $0.50，Sol $2 / $10，Astra $10 / $50。价格、上下文和可用路由以宿主实时目录或官方定价为准，不据此承诺固定节省比例。

## 推理档位

- `low`：单步、局部、容易核验。
- `medium`：日常多步骤工作，默认起点。
- `high`：复杂实现、较多依赖、多个方案比较或严谨调试。
- `xhigh` / `max`：仅在确实高不确定、高价值且验收困难时使用，避免作为日常起始档位。
- `ultra`：仅当宿主和所选模型支持，且前述档位仍不足时使用。

以宿主实时模型定义为准；若模型或档位不可用，报告差异，不冒充执行成功。

## 执行方式

主代理负责统筹和验收，先明确任务范围和验收条件，再选择直接执行或委派。主代理使用当前对话的实际模型，本技能不强制指定，也不能自动切换主代理模型。收到 `ROLE=EXECUTOR` 的子代理按已分配的任务执行，不重新进行主代理路由。

**直接执行**：仅适用于工作量小，且同时满足目标明确、影响局部、无需设计取舍、能立即核验的任务，例如解释一个简单问题、修正错别字、调整少量文档或明确且影响局部的配置值。不能只凭修改行数少判断。主代理负责实施、自检和交付。

**默认委派**：涉及功能实现、需要调查的缺陷修复、跨文件改动、批量处理或多步骤研究等实质性工作，且不满足上述直接执行条件时，由主代理规划并派给子代理。子代理负责执行、自测和修复；主代理检查实际 diff、产物和验证证据，完成最终验收。直接执行称为自检；发生委派且主代理另行检查产物与证据，才称为独立验收。

**按子任务选模型**：依据“三档选择”和“推理档位”分别为每个子任务选择模型与档位，不把整个项目的难度套到每个子任务上。派工前简要说明所选组合、理由、范围和验收条件。

**控制并行**：默认一名子代理；只有任务相互独立、文件归属清楚且并行有收益时才增加。主代理推进独立的准备与验收工作，避免重复实现子代理正在处理的内容。

**返工与升级**：先区分环境、信息缺失、实现错误和推理不足。优先给原子代理具体反馈和证据；确需升级时，由主代理选择新配置并交接。若复用工具不能改变已有子代理的模型或档位，应以新配置创建子代理，不把自然语言要求当成切换成功。子代理不自行改模型、升档、递归派工或作最终验收；关键假设被推翻或范围实质变化时，回报主代理决定。

**委派不可用**：说明实际限制；当前主代理能够胜任且用户未要求必须委派时，继续完成任务并自检。用户明确要求必须委派时，报告阻塞并保留交接材料，不擅自改为主代理实施。

用户明确要求“必须委派”或“直接完成”时，优先遵循用户要求。

支持模型覆盖的委派工具应显式传入 `model`、`reasoning_effort`；使用 `collaboration.spawn_agent` 时同时传入 `task_name`、`message` 和 `fork_turns: "none"`。委派消息包含 `ROLE=EXECUTOR`、目的、范围、已知事实、验收项、工作目录、相关文件及其归属、适用规则和交付格式。要求子代理交付实际结果、验证证据和未完成项，由主代理验收。

不要未经用户要求设置硬 token 或金额预算。委派增加规划、交接、报告和验收上下文，小任务可能不值得拆分。
